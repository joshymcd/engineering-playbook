## Prefer the smallest correct architecture

Start with one application package and one deployable unit. Add workspaces, packages, queues, databases, or abstraction layers only when a real ownership, deployment, reuse, or testing boundary demands them.

Small does not mean unstructured. Domain, transport, persistence, and UI boundaries should be visible from the first vertical slice.

## Build vertical slices

A useful slice crosses the entire system:

1. Domain contract and validation.
2. Persistence operation.
3. Server boundary.
4. Query or collection integration.
5. Working user interface.
6. Tests at the appropriate boundaries.

Avoid building every schema, then every endpoint, then every screen. Complete one representative workflow first and use what it teaches to shape the next slice.

## Make state ownership obvious

- The URL owns navigation and shareable filters.
- TanStack Query or DB owns remote and synchronized records.
- Routes and feature containers own composed views and list filters.
- Forms own drafts and submission state.
- Leaf components receive records and callbacks; they do not rediscover their own data.

## Keep trust boundaries strict

Browser input, route parameters, imported files, webhooks, and AI tool calls are untrusted. Validate them at the server boundary and enforce authorization again in the persistence operation.

## Optimize for replacement at real seams

Abstract a dependency when a replacement is plausible and the contract can be stated clearly. A repository interface is useful when moving from memory to DynamoDB is expected. A generic wrapper around every library is not.

## Confirm persistence before declaring success

Optimistic UI should feel immediate, but success messages, navigation, and form closure should wait for persistence when failure matters. For TanStack DB, await `transaction.isPersisted.promise`.

## Generated does not mean disposable

Generated route trees, migration metadata, and environment declarations may be committed. They are regenerated by tools, excluded from manual formatting where necessary, and never edited directly.

## Document exceptions

The repository README should explain choices that differ from the default: client-only rendering, URL-capability authorization, local-only persistence, human-only migrations, or a non-SST deployment target.
